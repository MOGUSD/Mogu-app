# MOGU — Visual design reference

## Source of truth

The two design images supplied by the product owner on 2026-11-14 are the visual references for the MVP:

1. **Product UI reference** — the first image: the target visual language and screen composition for the application.
2. **Brand logo and app icon reference** — the second image: the MOGU wordmark, mascot treatment, colors, and launcher-icon direction.

These references are design guidance, not permission to copy unrelated third-party assets or use the child’s portrait as a real user profile.

## Brand

- Product name: **МОГУ**
- Tagline: **Учусь • Говорю • Играю**
- Friendly, encouraging, child-centred visual identity.
- Rounded, large touch targets; soft blue, pink, lilac, mint, and warm yellow accents; dark navy text.
- Use the supplied logo artwork as the authoritative brand reference. Do not redraw or alter the wordmark casually.

## UI direction from the first reference

- A welcoming home screen with clear large cards for communication, learning, world around me, and emotions.
- Persistent, simple bottom navigation for Home, Progress, Parents, and Specialist.
- The communication board is a primary workflow: large pictogram cards, short labels, a clear phrase area, and prominent speech playback.
- Learning activities use large visual choices and calm feedback.
- Progress and profile views are visually separate from the child’s core communication workflow.
- Keep layouts responsive for phones and tablets; prioritize portrait touch use.
- Maintain readable contrast and generous spacing. Avoid dense screens, tiny controls, time pressure, penalties, or distracting animation.

## Product requirements remain authoritative

The master specification takes precedence over visual mock-up details:
- MVP supports Russian, Kazakh, and English.
- Core communication functions must remain usable offline.
- A category change must not clear the phrase being composed.
- Urgent communication cards (Pain, Help, Stop, Toilet) must remain readily available.
- Never make speech or learning outcomes guarantees.
- Do not collect or upload children’s personal data in the MVP.

## Implementation note

Treat the mock-up as a visual target, not as proof that every screen shown is in MVP scope. Build the communication experience first, then learning, emotions, progress, and profile surfaces in the agreed sequence.
